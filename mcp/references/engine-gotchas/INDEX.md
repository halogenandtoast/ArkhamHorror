# Engine gotchas index

Hard-won engine facts (timing, queue, matcher, persistence traps). Grep this directory before engine or card-timing work. `[[name]]` links refer to sibling files.

- [project_onlyskillTestsource_never_replaced_you](project_onlyskillTestsource_never_replaced_you.md) — `OnlySkillTestSource` was the ONE arm of `passesCommitRestriction` (`Helpers/SkillTest.hs:691`) that skipped `replaceYouMatcher`, so an unsubstituted `You` fell through to `Game.hs:1267` and resolved to **`gameActiveInvestigatorId`**. The commit step asks every seat at once and each commit re-points the active investigator, so Crack Shot (11057, "a [[Firearm]] or [[Ranged]] asset **you control**") was offered to Jenny while she was active and then silently vanished when Carolyn committed a card — no error, just a shorter list (#5862). The general trap: a `You` reaching `select` unsubstituted is not an error, it quietly means the active investigator, which is neither the turn investigator nor the skill test performer. Reproducing it needs two seats AND the other seat's commit injected first
- [project_resolves_story_window](project_resolves_story_window.md) — `ResolvesStory Timing Who StoryMatcher` is the story-resolution window, added 2026-10-16 (there was none at all before); `#when` is raised on `ResolveStory` and `#after` on `ResolvedStory`, both gated on `ResolveIt` and both while the entity is still in play so `StoryWithTrait` resolves. `ResolvedStory` gained the resolver — `ResolvedStory InvestigatorId StoryMode StoryId` — because a story-only `Who` would otherwise offer the Forced to every seat ([[project_forced_window_who_must_be_you]]). **`#when` cannot cancel the story**: the Game raises it from its own handler for `ResolveStory`, which runs AFTER every entity handled that message, so the card has already pushed its effects; `CancelEffects` is read only on the encounter-draw path and in `SkillTest/Runner.hs`. Cancel the queued `ReadStory` instead — no entity, no effects, no `ResolvedStory`, so an act watching `#after` takes no clue

- [project_damage_vs_shroud_forced_must_ride_the_placement](project_damage_vs_shroud_forced_must_ride_the_placement.md) — a "damage on <room> equal to its shroud value" **Forced** must hang off `PlacedToken #after … #damage`, NOT `forced AnyWindow`, even though AnyWindow is the engine's idiom for a state-triggered Forced (Café Luna, Rainy London Streets, Barrier Core). Both shroud fields give the MODIFIED shroud (`LocationJustShroud` is `getModifiedShroudValueFor`, `Game.hs:4876`), so a Flashlight/Lantern reduction dips it for the duration of an investigation and a room at damage 1 / printed shroud 3 reads `1 >= 1` — an AnyWindow Forced then collapses a room that took no new damage, and `onlyOnce` just spends its one use on the false positive. Riding the placement means the criterion is only evaluated when damage actually arrived. Cost: a PERMANENT shroud decrease onto existing damage will not trigger the flip. The opposite trap is [[project_always_true_forced_on_anywindow_makes_a_card_unplayable]] — there the criterion never falsifies; here it does, but it becomes true when nothing happened

- [project_always_true_forced_on_anywindow_makes_a_card_unplayable](project_always_true_forced_on_anywindow_makes_a_card_unplayable.md) — a **Forced** ability on `AnyWindow` whose criterion never stops holding does not merely loop: the card carrying it CANNOT BE PLAYED. The choice is still offered, answering it does nothing, and the scenario step counter not moving is the only tell — no error, no log line. A forced ability must resolve at every eligible timing point, `AnyWindow` matches every window including the ones opened while the card is being played, and the criterion never falsifies itself, so the play never completes. The exact opposite of [[project_anywindow_reaction_nests_in_its_own_activation]], where `freeReaction AnyWindow` is the CORRECT reading of a condition-only `{reaction}` — the two differ on whether the ability may decline to fire. "If X, discard it" for a state rather than a moment wants one of three other shapes: a step at the end of whatever changes the state (where the card usually means it), a Forced on the window where the state CAN change (`SpentUses`, `PlaceTokens`), or an asset's own `whenNoUses` field — which has no def-level form and no event equivalent at all. Nothing static catches it: the def validates, every constructor exists, no binding is unbound

- [project_jsonb_columns_cost_40_percent_over_json](project_jsonb_columns_cost_40_percent_over_json.md) — a `jsonb` column stores identical content **+38–40%** larger than `json` or `text` (which measure byte-identical): per-element JEntry headers plus key reordering (shortest-first) destroy the locality pglz's window compresses on. TYPE` rewrites the relation and needs headroom equal to the table, so on a 94 GB table the fix is a new nullable column plus a read fallback, never a type change. Measuring any of this has four silent traps: `pg_column_size` returns the 18-byte TOAST *pointer* for out-of-line values; a value is only compressed once *stored*, so an expression or a CTE reports the uncompressed datum; `INSERT ...
