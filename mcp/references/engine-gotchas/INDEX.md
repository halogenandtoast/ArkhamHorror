# Engine gotchas index

Hard-won engine facts (timing, queue, matcher, persistence traps). Grep this directory before engine or card-timing work. `[[name]]` links refer to sibling files.

- [project_forced_initiation_splits_damage_and_horror](project_forced_initiation_splits_damage_and_horror.md) — a forced ability initiates once per timing POINT, and `runWindow` derived the points per matching *window* (#5743). `InvestigatorDealtDamageOrHorror`/`AssetDealtDamageOrHorror` match both `Window.DealtDamage` and `Window.DealtHorror`, which `finalizeDeferredDamageAssignment` raises in ONE `CheckWindows` batch — so a 1-damage/1-horror attack gave Spectral Shield two initiations: `Do (UseAbility)` asked which `primaryWindowTarget` to resolve (two identical buttons, both the same investigator), each use then saw one window so `getTotalDamageAmounts` returned `(1,0)` and the card's `damage > 0 && horror > 0` branch never fired, and the leftover initiation survived `GroupLimit PerWindow 1` (counted by window intersection) and ate the horror too, for a second Charge (#5785). Points are now `Window.windowEventGroups`, grouping `DealtDamage`/`DealtHorror`/`TakeDamage`/`TakeHorror` by source+target+timing; BOTH the `initiationsFor` split and the `Do (UseAbility)` target ask must use it. Not `windowIsSingleEvent`: the Amaranth cards are forced on `AssetDealtDamageOrHorror #when … AnyAsset` and read only the head window, so they must stay one initiation per asset. The non-forced branch never split, hence Flesh Ward / Idol of Xanatos / Guard Dog (2) were fine
- [project_criteria_override_must_ride_on_the_choose_not_a_skilltest_modifier](project_criteria_override_must_ride_on_the_choose_not_a_skilltest_modifier.md) — a `CriteriaOverride` handed to `skillTestModifier` never reaches the prompt: `WindowModifierEffect`'s `EffectSkillTestWindow sid` arm only `tell`s `when (msid == Just sid)`, and the test is not created until `EvadeEnemy`/`FightEnemy`, downstream of `ChooseEvadeEnemy`. Not a queue-order bug — reordering the pushes changes nothing. `ChooseEvadeEnemy` ends in `unless (null choices)`, so the card resolves in total silence: Bait and Switch (3)'s "evade a non-Elite enemy at a connecting location and switch places" did nothing at all (#5780). The tell is a label/choose mismatch, because the label's `selectAny $ CanEvadeEnemyWithOverride override` evaluates the override directly. Put it on the choose — `mkChooseEvadeMatch`, or `chooseEvadeOverride = True` as Guerrilla Tactics does
- [project_forced_pass_must_not_rewrite_the_difficulty](project_forced_pass_must_not_rewrite_the_difficulty.md) — only an AUTOMATIC success has total difficulty 0; a forced `SucceededBy NonAutomatic n` (Scrape By (1), Lab Coat (1), via `passSkillTestBy`) keeps the real difficulty. `PassSkillTestBy` used to fake succeed-by-0 by writing `difficultyL .~ Fixed 0` plus a fabricated `SkillTestResultsData n 0 0 0`, so `stmModifiedDifficulty`/`stmValueBreakdown`/the skill value all read 0 and the panel showed `0 VS 0` at shroud 5 (#5775). Now the tested values are published for real and the override is marked `skillTestResultForced`, which `RecalculateSkillTestResultsCanChangeAutomatic` short-circuits on and the frontend gates its succeeded-by read on
- [project_custom_card_step_keys_live_in_two_places](project_custom_card_step_keys_live_in_two_places.md) — a custom-card step's keys live INSIDE its value when `runSteps` hands it to a handler (`{"chooseFrom": {"bind": …}}`, because the handler reads `specObject spec`) and BESIDE it when the guard arm handles it itself (`{"let": "x", "be": …}`, `if`/`when`'s `then`/`else` via `branch`). The wrong place is never looked up, so the option defaults and any `$binding` it should have made stays an unsubstituted string that then fails to decode. Also: the skill-test steps share `beginTest` for `modifiers`/`onReveal`/`onSuccess`/`onFailure`/`by`, `withTestSkill` reads `skill`/`insteadOf` through a local `field k = KeyMap.lookup k o`, and `request`'s `on`/`steps` are read by `runCustomHandlers`, not `runRequest`
- [project_open_windows_live_in_two_places](project_open_windows_live_in_two_places.md) — an open window lives in more than one place: `CheckWindows` AND the materialised forced-initiation set `ResolveWindowInitiations` (#5743), which by resolution time sits behind a `MoveWithSkillTest` that `QueueWrapper Message` neither strips nor groups. `PerWindow` limits INTERSECT the ability's current windows with `usedAbilityWindows`, so `ReassignDamage` rewriting only `CheckWindows` + the used record left the pending set stale and the limit vacuous — Diving Suit reassigned the same Slitherer in Darkness attack onto itself forever, 14 damage on a 3-health asset (#5769). `replaceWindowMany` is now a `mapQueue` covering both carriers and recursing through `Do`/`MoveWithSkillTest`/`Priority`/`Retain`/`Run`/`Simultaneously`
- [project_defeated_attacker_must_finish_its_attack](project_defeated_attacker_must_finish_its_attack.md) — defeat does NOT cancel an attack already in flight (FAQ 1.4 nested sequences). A `#when EnemyAttacks` interrupt that kills the attacker — Aquinnah (3) redirecting the damage onto it, which its reminder text explicitly prices at "you still take horror dealt by the attack" — lost the attack entirely: `ResolvedAbility` runs `clearRemovedEntities` BEFORE `PerformEnemyAttack`, deleting the entity, and the handler's `not enemyDefeated` guard skipped it anyway. Now `EnemyAttack`/`Do (EnemyAttack)` are gated on `not enemyDefeated` (an enemy never *starts* an attack while dead) while `PerformEnemyAttack` allows `isJust enemyAttacking`, `attackingL` is cleared in `After (EnemyAttack)` (it never was — which also un-breaks the `AttackingEnemy`/`NotAttackingEnemy` matchers), and `clearRemovedEntities` keeps a mid-attack enemy. Daniela Reyes' `HistoryEnemiesAttackedBy` fell through the same hole
- [project_aquinnah_redirect_is_a_damage_replacement](project_aquinnah_redirect_is_a_damage_replacement.md) — Aquinnah's "deal that enemy's damage to any enemy, **instead**" is a replacement for the attack's damage step, not an immediate effect in the `#when EnemyAttacks` window. It used to `chooseDamageEnemy` inside the window, so a Dodge played afterwards cancelled an attack whose damage was already on the board. The redirect is now registered on the attack (`attackDamageReplacement :: [Message]`, alongside `attackDealDamage = False`) and pushed by `PerformEnemyAttack` under the same `allowAttack && not details.cancelled` guard as the attack's own damage — so a later Dodge zeroes the redirect too, while Aquinnah keeps her paid exhaust + 1 horror. Also adds `updateAttackDetails`: `changeAttackDetails` callers all hold the window's **frozen** copy and blindly overwrite whatever `Do (EnemyAttack)` or another card in the window wrote
- [project_investigatable_location_excludes_unrevealed](project_investigatable_location_excludes_unrevealed.md) — `InvestigatableLocation` is `LocationShroud isJust` + no `CannotInvestigate`, and `LocationShroud` returns **Nothing for any unrevealed location**, so it means "investigatable right now", never "investigatable once I'm standing there". That gates move-then-investigate cards off their own move target: Duke, parked at Your House under a Locked Door's `CannotInvestigate` with only an unrevealed Rivertown connecting, lost ability 2 from the question entirely. Use `PotentiallyInvestigatableLocation` (printed shroud + no `CannotInvestigate`) on the move branch, plain `InvestigatableLocation` on the "here" branch, and pass the whole `oneOf` to `withInvestigationTargetsMatching` — `withInvestigationTargets` ANDs `InvestigatableLocation` onto whatever you give it. Criterion and `Helpers/Ability.hs` `getCanAffordAbilityCost` re-select the SAME stored matcher, so they must agree. Remote-investigate cards (Dowsing Rod, In the Know (1), Local Map) do not want this
- [project_skilltestat_matches_the_target_location](project_skilltestat_matches_the_target_location.md) — `Matcher.SkillTestAt loc` resolves to `targetMatches st.target (TargetAtLocation loc)`: it asks where the test's TARGET is, not where the investigator is (`SkillTestAtYourLocation` does that). So `SkillTestAt (locationWithEnemy a)` on an enemy's own ability is vacuously true whenever the test targets that enemy — The Beast in a Cowl of Crimson's "after you fail a skill test while at its location" fired off Swift Retreat, which tests agility against the *nearest* Coterie enemy from another location (#5698). Printed "while at X's location" constrains YOU: put it in the window's `Who` as `You <> at_ (locationWithEnemy a)` with `AnySkillTest`
- [project_asset_controlled_by_saw_hand_cards](project_asset_controlled_by_saw_hand_cards.md) — a card still in HAND can have a real `Asset` entity (`StillInHand iid` + `assetController = Just iid`): `cdCardInHandEffects` preloads (Occult Scraps, G-Men, …) and `withCardEntity @AssetId` temporaries (both Robert Castaigne printings, Ad Hoc, Pushed to the Limit, Knowledge Is Power). `AssetControlledBy` read only the controller field, never the placement, so **every** "an asset you control" select saw it — Custom Modifications became playable off a Firearm Robert Castaigne (4) had merely revealed from hand, and its attach prompt targeted an asset with no board presence: nothing to click (#5695). Fixed by excluding `StillInHand` in `AssetControlledBy` plus an `AssetWithPlacement (StillInHand iid)` fallback in `Criteria.ControlsThis`, the one consumer that needs it (the borrowed Firearm's own `ControlsThis` fight ability). `AssetOwnedBy`/`OwnsThis` unchanged — you *do* own a card in hand
- [project_simultaneously_isolates_the_queue](project_simultaneously_isolates_the_queue.md) — a `Simultaneously` branch runs through the full pipeline with the queue CLEARED and only the interleaved result restored afterwards, so game state threads across branches but the queue does not. Three traps: a read-modify-write store bump reads the same stale value in every branch (use `IncrementGlobal`/`InsertGlobal` + the deferred `CounterBumped`/`GlobalInserted` check); `Priority` is unwrapped to a PLAIN push inside a branch, so it keeps the message but loses its queue-jumping protection; and a nested `Simultaneously` (the interleave splices branch output verbatim) had no `runGameMessage` case and was dropped whole — fixed with `Simultaneously {} -> g <$ push msg` (#5694). Corollary: do not tally anything important through the campaign store — Bird Hunting still read 1 after 3 simultaneous Whippoorwill deaths; count off `getAllHistoryField #turn HistoryEnemiesDefeated`, which `runGameMessage` writes synchronously (#5691, #5694)
- [project_standalone_scenarios_earn_no_achievements](project_standalone_scenarios_earn_no_achievements.md) — `newScenario = newGame . That`, so a standalone scenario has no `Campaign`; `currentCampaign` returns Nothing, which gates `earnAchievement`, `achievementProgress` and every `whenEligibleCampaign`. Intended, not a bug (#5691). In an export, `gameMode | keys` is `["That"]` and `"This"` appears 0 times; the game's NAME is the campaign name even for standalone, so it proves nothing
- [project_addtohand_resurrects_removed_from_game_cards](project_addtohand_resurrects_removed_from_game_cards.md) — `AddToHand` had no removed-from-game guard: `obtainCard`/`ObtainCard` only clears `foundCards`/`focusedCards`, never `removedFromPlayL`, so a delayed "return this to your hand" put the card in hand while it stayed removed. Agatha Crane removes the event she plays from the discard, but Read the Signs (2) had already queued `atEndOfTurn … addToHand` (#5688). Same hole for Spectral Razor (2) / Pilfer (3) / Breaking and Entering (2) under Eidetic Memory (3), The Painted World, De Vermis Mysteriis (2); guarded at the choke point in `handleAddToHand`
- [project_labeledi_erases_i18n_vars](project_labeledi_erases_i18n_vars.md) — `labeledI` has no `HasI18n` constraint and rebinds `withI18n` itself, wiping `?scopeVars`, so `withI18n $ countVar 2 $ labeledI "drawCards"` ships `$label.drawCards` with no `count`. Plural keys silently fall back to the "1" branch (True Awakening (2) drew 2 and said "Draw 1 card", #5686) and non-plural keys like `"Heal {count} damage"` render with a hole. Use `labeled` (or `unscoped $ countVar n $ labeled` inside a `scenarioI18n $ scope` block); `labeledI` is only for var-less labels
- [project_disableeffect_reran_ondisable_for_removed_effect](project_disableeffect_reran_ondisable_for_removed_effect.md) — `DisableEffect` used `maybeEffect`, which falls back to `gameActionRemovedEntities`, so a second `DisableEffect` for the same effect found the `finished = True` copy and ran `effectOnDisable` AGAIN. One duration is ended by several messages — `EffectMoveWindow` fires on `MoveAction _ _ _ False`, `Move _` and `ResolvedMovement` — so every `afterMove` body ran up to 3x (Close Watch spawned an enemy per trigger; the only other caller was idempotent so it never showed). Fixed by looking up the live effect only
- [project_after_dealt_damage_is_post_defeat](project_after_dealt_damage_is_post_defeat.md) — `after DealtDamage` on an enemy now fires BELOW `Damaged`, so a lethal hit has already defeated and discarded the enemy when the window opens (Rules Ref "Dealing Damage/Horror" step 2 + FAQ 1.4 nested sequences). The trigger still fires, but every board read sees the corpse gone — Special Investigation stopped making a dead Arkham Officer attack (#5682). Matchers must use the removed-tolerant `Helpers/Window/Enemy.enemyMatches`, and a clause nested under `EnemyAt`/`locationWithEnemy` on the damaged enemy will not hold. The investigator and asset cascades still use the old pre-application order
- [project_forced_window_who_must_be_you](project_forced_window_who_must_be_you.md) — `Do (CheckWindows)` runs for EVERY investigator and each pushes `UseAbility` with itself as `iid`, so a Forced window whose `Who` is only location-scoped (`at_ (locationWithEnemy a)`) is offered to everyone there and "that investigator" resolves to whoever answers first. Gang Enforcer attacked the wrong seat (#5685), Rookie Cop damaged all of them. Scope `Who` with `You <> at_ (...)`
- [project_divided_damage_must_batch_per_enemy](project_divided_damage_must_batch_per_enemy.md) — every `DealDamage` on an enemy opens its OWN `WouldTakeDamage` window, so a "assign N damage divided as you choose" card must push one message per enemy carrying that enemy's total, not N one-point messages; Flamethrower (5)'s `replicateM_` made Mimetic Nemesis' Forced ability fire 4 times and expose 4 concealed mini-cards for one attack. Use `chooseEnemyAmounts` + `ResolveAmounts`, and `MaxAmountTarget` because the wording is "up to N" (#5665)
- [project_health_modifier_drop_never_rechecks_defeat](project_health_modifier_drop_never_rechecks_defeat.md) — defeat is rechecked only when damage is ASSIGNED, never when an enemy's modified health FALLS to or below the damage already on it, so clue/stack-scaled bosses sit in play overkilled (Randall Tillinghast #5729, Nyarlathotep True Shape #5749, Anette Mason). The modifier itself applies fine, so exports look healthy. Add an intercept on whatever message changes the quantity — for clue-scaled health that is `After (GainClues {})` -> `checkDefeated`, which covers both the plain `GainClues` and `Do (DiscoverClues ...)` paths
- [project_resign_then_game_end_fires_both_windows](project_resign_then_game_end_fires_both_windows.md) — a forced ability on `oneOf [GameEnds #when, InvestigatorEliminated #when You]` fires TWICE when an investigator resigns and then ends the scenario; the default `GroupLimit PerWindow 1` only dedupes inside one window. Cap it with `onlyOnce` (= `groupLimit PerGame`); TDC Tasks go through `taskEndsAbility` in the campaign Helpers (#5650).
- [project_affectsothers_drops_include_eliminated](project_affectsothers_drops_include_eliminated.md) — `affectsOthers`/`affectsOthersKnown` wrap the matcher in `InvestigatorIfThen(Known)`, and `Game.hs`'s `includeEliminated` has no case for those constructors, so an inner `IncludeEliminated` is silently lost and the select returns nothing once everyone is eliminated. Put `IncludeEliminated` on the OUTSIDE of the wrapper (#5650).
- [project_enemyspawns_window_carries_placement](project_enemyspawns_window_carries_placement.md) — `Window.EnemySpawns` carries a `Placement` and its matcher a `PlacementMatcher` (`AnyPlacement` / `PlacementAt`), so a `Concealed X` enemy spawning into the shadows still opens one spawn window; `PlaceEnemy` no longer also emits `EnterPlay` during a spawn (#5649).
- [project_defeated_investigator_unselectable_in_own_elimination_window](project_defeated_investigator_unselectable_in_own_elimination_window.md) — on the DEFEAT path (not resign) `defeatedL` is already set when `#when InvestigatorEliminated` opens, so every investigator `select` drops the investigator and `ControlsThis` silently fails; every Drowned City Task lost its progress when its owner died (#5619). Fixed by `.includeEliminated` in `ControlsThis`/`OwnsThis` — do NOT move `defeatedL`, three engine sites depend on the order. A plain `You`/`locationWithInvestigator iid` in an elimination window still resolves to nothing
- [project_asset_event_builder_lists_are_manual](project_asset_event_builder_lists_are_manual.md) — `Asset.hs`/`Event.hs` keep `allAssets`/`allEvents` as HAND-maintained builder lists; every other card type is generated by `cards-discover --builders=` and cannot drift (`Asset/Assets.hs` is `--dir=` only: exports, not registration). A forgotten entry is a runtime `error "Unknown asset: ..."` 500 on first use, with card def, impl module and art all present — Children of Blood shipped 2 of its 6 assets registered (2026-09-04)
- [project_attackisvalid_is_the_direct_enemyattack_gate](project_attackisvalid_is_the_direct_enemyattack_gate.md) — `CannotBeAttackedBy` is filtered on the `EnemyWillAttack` path only; retaliate, alert and `EnemyAttackIfEngaged` push `EnemyAttack` directly, so `attackIsValid` (`Arkham/Attack.hs`) is the single shared gate — Elokoss retaliated through her own "cannot attack you" evade modifier (#5583)
- [project_leave_play_tombstones](project_leave_play_tombstones.md) — `gameTombstones` is THE way to read an entity back after it leaves play (assets and enemies): a frozen pre-removal snapshot, revived ambiently via `runReaderT g'` only while a leave-play/defeat window names that entity. Enemies park **pre-dispatch** in `runPreGameMessage` because `runGameMessage` runs last, after the Enemy runner has already cleared their keys. Cancellation is correct for free — cancel the defeat and the windows go with it, so the snapshot is never consulted. Replaced nine copies of `orM [DefeatedEnemy m, m]` and the `EnemyAt`→`EnemyWasAt` rewrite (#5518, #5557)
- [project_ifenemydefeated_resolves_after_disposal](project_ifenemydefeated_resolves_after_disposal.md) — `closeDefeat` pushes `[EnemyDefeated #after] <> disposal <> [IfEnemyDefeated #after]`, so `IfEnemyDefeated` sees the card already discarded; reading the enemy back no longer needs a decorated matcher (tombstones), but a trigger that REPLACES the disposal still must use `EnemyDefeated #when` + `insteadOfDiscarding`. The durable ledgers (`scenarioDefeatedEnemies`, `historyEnemiesDefeated`) are a separate concern, both written from `Do (Defeated …)` + `RecordDefeatedEnemy` (#5529, #5557)
- [project_addtovictory_leaveplay_window_ordering](project_addtovictory_leaveplay_window_ordering.md) — the enemy victory-display path has TWO opposing timing constraints: `#when`/`#at LeavePlay` must fire before `RemovedFromPlay` (plain `select` drops out-of-play enemies, and `RemovedFromPlay` discards attached assets) or Recover the Relic's Objective never fires (#5554); `#after LeavePlay` must fire from inside `Do (AddToVictory …)` so Corner the Suspect sees the card in `scenarioVictoryDisplay`. Collapsing either way re-breaks one card. Knock-on: a resolution pushed from that window fires with the enemy still in play, so `Scenario.hs`'s pre-`clearQueue` net must match the queued `Do (AddToVictory …)` rather than `OutOfPlayEnemy RemovedZone EnemyWithVictory`
- [project_asset_addtovictory_keeps_tokens](project_asset_addtovictory_keeps_tokens.md) — assets added to the victory display kept every token; `OutOfPlay VictoryDisplayZone` is not `Placement.outOfGame`, so the entity stays selectable and `getDoomCount`'s asset aggregation (no in-play filter, unlike `InPlayEnemy` for enemies) kept counting a defeated Key Locus' doom toward the agenda. `Enemy/Runner.hs` already cleared `tokensL`/`keysL`; `Asset/Runner.hs` did not (#5680)
- [project_transfigured_form_field_overrides](project_transfigured_form_field_overrides.md) — `TransfiguredForm` overrides printed values **one field at a time** in the `Game.hs` field block (health/sanity/base skills/traits); `InvestigatorClass` was missed, so a transfigured Luke Robinson still reported Mystic to `InvestigatorWithClass` / `DifferentClassAmong` (#5544). - [project_handwith_excludes_asifinhand_cards](project_handwith_excludes_asifinhand_cards.md) — `HandWith` is `field InvestigatorHand` (literal hand only), so a self-referential `HandWith (HasCard (CardWithId a.cardId))` matches **nobody** for an as-if-in-hand card even though the entity exists; Join the Caravan (1) reduced its own cost by 0 when Norman Withers played it off his deck top (#5544).
