title: project-achievements
description: "Above-the-table achievements system — typed PersistField storage, runMessages-logger earn pipeline, per-campaign detection modules; NOTZ, Dunwich, Carcosa, TFA, Circle + Drowned City done"
---

Achievements (official campaign lists, ~185 total; done as of 2026-08: Return to NOTZ 14, Return to Dunwich 15, Return to Carcosa 16, Return to TFA 16, Return to Circle 15, and **The Drowned City 20** — the first list printed for the base campaign itself (id "11"), so there is no Return-to variant to inherit the hook):

- **Types**: `Arkham.Achievement.Types` — per-campaign enums (`NightOfTheZealotAchievement`) merged in `data Achievement`, flat-name JSON AND a **`PersistField`/`PersistFieldSql` instance** (stores constructor name as text, parses back typed — the entity column is `achievement Achievement`, never raw Text; keep constructor names globally unique, disambiguate "Line in the Sand"-style repeats per campaign).
- **DB**: `Entity/Arkham/Achievement.hs` → `arkham_achievements` (userId cascade, achievement, earnedAt Maybe, arkhamGameId Maybe **OnDeleteSetNull** = link degrades on game delete, progress jsonb for cross-playthrough shapes, UniqueUserAchievement). Migrations are hand-managed — table SQL was given to the user.
- **Earn pipeline**: engine pushes `EarnAchievement` via `Arkham.Achievement.earnAchievement` which self-gates on `settingsAchievementsEnabled` (creation-time optional, default ON; only shown for supported campaigns) + `achievementCampaigns` (Return-to gating). `updateGame` (Games/Shared.hs) collects them via the **otherwise-unused `runMessages` message-logger slot**, `insertUnique`s one row per human player in-transaction, broadcasts `GameAchievement` ApiResponse only for new earns.
- **Detection**: per-campaign module (`Arkham.Campaign.Campaigns.NightOfTheZealot.Achievements`) hooked at the top of the campaign's runMessage (`lift (runNotzAchievements msg) *> case ...`); Return-to inherits via delegation. Campaign-persistent trackers use the campaign store (`SetGlobal CampaignTarget` + `stored` from Helpers.Campaign); campaign dispatches BEFORE entities so defeated enemies are still queryable at Defeated time.
- **earnAchievement pushes `Priority (EarnAchievement …)`** — earns often coincide with act advances/resolutions whose handlers clearQueue (a real-game Zealot's Revenge earn was wiped this way); Priority messages pop next regardless of queue position. Player-CHOICE achievements (I Don't Trust Her) attach the earn to the actual decline branch via `addCampaignCardToDeckChoiceWhenDeclined` (Lifted variant takes a QueueT continuation for the decline) rather than inferring from later state.
- **NEVER key detection on the `ScenarioResolution` message itself**: the Scenario wrapper (Arkham.Scenario ~line 515) clearQueues TWICE while processing it (once entering resolution + once on the re-pushed copy), so even Priority pushes made during that dispatch are wiped. Key on what the resolution WRITES (Record/RecordCount) or, when a resolution records nothing (Essex R1), on the scenario's post-clear re-entry message (`DoStep 1 (ScenarioResolution _)` for Essex-style `doStep` resolutions). **The general escape hatch is `EndOfGame`**: `endOfScenario`/`endOfScenarioThen` push it from the resolution BODY, i.e. after both clearQueues, and it only queues `EndOfScenario` (which is what tears the board down) — so at `EndOfGame` dispatch the full board is still readable (location reveal/flood state, controlled Artifacts, victory display). Drowned City hangs four scenario-end achievements off it. To tell a real resolution from No Resolution there, check `selectAny UneliminatedInvestigator`: No Resolution is only reached once every investigator has resigned or been defeated, so a surviving uneliminated investigator means a numbered ending.
- **Asset enters-play signals differ by path**: controlled plays/TakeControl fire `CardEnteredPlay`; uncontrolled story assets placed at locations only get `PlaceAsset` (inline for the play path, so match both). In specs, three allies can't all be `putAssetIntoPlay` (ally-slot fights discard the earlier ones) — direct-insert the first N via `testAssetWithDef`.
- **Win-time investigator checks must use `IncludeEliminated`**: plain investigator matchers exclude resigned/defeated investigators, and winning resolutions often happen after everyone resigned (LiTaS tear). Pair with `AliveInvestigator` to still exclude killed/insane. **And never use investigator liveness as a proxy for "the scenario was beaten"** — `selectAny UneliminatedInvestigator` looks like a No-Resolution discriminator but several scenarios are *won by resigning* (Court of the Ancients' final act objective is literally `AllUndefeatedInvestigatorsResigned`), so every investigator is eliminated at the winning moment and the check is always False. Key "beaten" on the final act's `AdvanceAct` instead: `ActId` is the act's card code, the campaign sees it before the act does, and the board is still intact. (Cost two silently-unearnable Drowned City achievements.) Damage-taken achievements ("take 10 damage"): count the WHOLE assignment (soak on assets included) per the user's ruling, not just points on the investigator; entity checks at Defeated time must use projection (`fieldMay`), not matchers — assets can remove themselves mid-ability and only `actionRemovedEntities` still has them (Alchemical Concoction).
- **Campaign-store tracker writes (`SetGlobal`) sink behind the message cascade of the very message that triggered them** — a spec's next `run` PREPENDS and jumps ahead; use `pushEnd` + `runMessages` (or resolve all pending prompts) when a later assertion depends on the store write having landed.
- **Frontend**: `src/arkham/achievements.ts` catalog + `ACHIEVEMENT_CAMPAIGN_IDS`, AchievementToast (vue-toastification, i18n at call site — toast container has no i18n context), CampaignLog "Achievements" tab (earned-only rows), `/achievements` page, i18n scope `achievements.json`.
- Endpoints: `GET /arkham/achievements`, `GET /arkham/games/:id/achievements`.
- **Cross-playthrough checklists** (Gang's All Here, First Steps, Member These, Case Closed): detection reports items via `achievementProgress`/`AchievementProgress Achievement [Text]` (never EarnAchievement); item keys defined in `achievementChecklist` (Types) and mirrored in frontend `achievementChecklists` + i18n `entries.<tag>.items.<key>`. API layer (`applyAchievementProgress` in Games/Shared.hs) merges keys into the row's `progress` jsonb array per user and flips earnedAt+gameId when complete. Progress rows have earnedAt/gameId null; clear endpoints only delete earned rows. **Every checklist detection needs a `CampaignStep _` sweep** re-deriving items from the campaign log (idempotent — API merge dedupes): moment-of-record detection alone misses campaigns whose records predate the feature. Specs trigger the sweep with `CampaignStep (InterludeStep 99 Nothing)` (unhandled step number → Runner catch-all no-op). Campaign-log tab shows the checklist from user-wide rows (`fetchAchievements`), not game-scoped rows.

**How to apply:** new campaign's achievements = new enum + `achievementCampaigns` entry + detection module hooked into that campaign's runMessage + frontend catalog/i18n entries + add campaign id to `ACHIEVEMENT_CAMPAIGN_IDS`.
