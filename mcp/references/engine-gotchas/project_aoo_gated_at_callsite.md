---
title: project_aoo_gated_at_callsite
description: "ActionDoesNotCauseAttacksOfOpportunity is enforced at each action's call site, not in the CheckAttackOfOpportunity handler"
---

The `CheckAttackOfOpportunity` message handler (`Enemy/Runner.hs` ~1952) does NOT consult `ActionDoesNotCauseAttacksOfOpportunity` — it only checks engagement plus `CannotMakeAttacksOfOpportunity`/`CannotAttack` on the enemy. Each action handler is responsible for gating whether it pushes `CheckAttackOfOpportunity` at all, based on the action-typed modifier.

Fight/engage/investigate gate correctly (e.g. `Investigator/Runner.hs` engage: `Will/CheckAttackOfOpportunity | ActionDoesNotCauseAttacksOfOpportunity #engage notElem modifiers'`). The basic **Draw** action (`Investigator/Runner/Card.hs` `handleDrawCards`) and **Resource** action (`Investigator/Runner/Action.hs` `handleTakeResources`) historically pushed it UNCONDITIONALLY — bug #4936 (Dr. Henry Armitage / Spreading Flames `c12115` first-action AoO prevention ignored on a Draw). Fixed by fetching `getModifiers iid` and gating both pushes on `ActionDoesNotCauseAttacksOfOpportunity #draw`/`#resource notElem modifiers'`.

`TakeActions` (→ `PayForAbility`/`AbilityEffect`) does NOT record `actionsPerformed` early; the write happens via `PerformedActions` (only for FastAbility in `ActiveCost.hs`) and `TakenActions` (end of action). So at action start `investigatorActionsPerformed` is still empty — correct time to read the "first action" modifier. The play-a-card path (`ActiveCost.hs` ~1571) gates via `modifiersPreventAttackOfOpportunity`. See [[project_basic_attack_enemy_source]] for related AoO/source nuances.

The ability path is gated twice: `ActiveCost.hs` `ForAbility` turns `ActionDoesNotCauseAttacksOfOpportunity` into `aoo = Just AnyEnemy`, and `startAbilityPayment`'s `checkAttackOfOpportunity` re-checks it (that second check used `||` where it meant `&& not` until Sep 2026).

The basic **move** action is `AbilityMove` on the *destination* location (`HasAbilities LocationAttrs`), so its `abilitySource` is where you are moving TO, not FROM. `MovingToDoesNotProvokeAttacksOfOpportunity LocationMatcher` (investigator modifier, matched against that source) is how "moving between these locations does not provoke" is expressed — the FROM side comes from whoever grants the modifier (Circus Ex Mortis' Big Top rings grant it to investigators at them).

A move action is not always a move ability: **move events** (`cdActions = #move` — Astral Travel, Scout Ahead, Physical Fitness, The Truth Beckons) would otherwise pick their destination while resolving, i.e. AFTER the AoO fires. So `ActiveCost`'s `ForCard` branch creates a **pending event** for any event whose actions include `#move` (the seam that already existed for `OrActions`): `CreatePendingEvent` + `BeforePlayEvent`, the card asks where it is going, stores the answer with `UpdateEventTarget`, and resumes with `CreatedCost acId`. On the second pass the destination is read back off `EventPlayTarget` and the AoO is decided before costs are paid; `Game/Runner.hs`'s `PutCardIntoPlay` keeps the answer (`eventTarget = mtarget <|> eventTarget attrs`) so the event resolves against the target it already chose. Scout Ahead pre-chooses only its FIRST move (the other two are not actions and cannot provoke).

**No destination means it provokes.** An event that reaches costs with no `EventPlayTarget` moved nothing between exempt locations (Scout Ahead's "done moving", Physical Fitness with nowhere to go), so the normal AoO stands. Same for an ability whose source is not the destination location. Deferring the check past the move was tried and is wrong: engagement is re-read at that point, and a **Massive** enemy does not travel with you, so the investigator is no longer engaged and nobody attacks (seen with Disguised Monstrosity, Circus Ex Mortis). A new move event that wants an exemption must pre-choose its destination in `BeforePlayEvent`.

**A forced ignore used to be completely silent.** `Enemy/Runner.hs`'s `EnemyAttack` handler splits on `canIgnore` (`MayIgnoreAttacksOfOpportunity{,Of}` — offers a choice) vs `willIgnore` (`IgnoreAttacksOfOpportunity` — mandatory). The mandatory branch pushed *nothing*: no `Do (EnemyAttack …)`, no window, no log line — and it runs **after** `EnemyWillAttack`/`EnemyAttacks` have already asked the player to resolve the attack (`ChooseOneAtATime`). The player clicked an attack prompt and watched it evaporate (#5600, Andy Van Nortwick vs Coral Star Spawn). It now emits a log line the same way the retaliate branch does (~line 1329): `log.attackOfOpportunityIgnoredBy` with a `source` var when the granting `Modifier` carries a card (read via `getFullModifiers`, whose `Modifier` keeps `modifierSource`/`modifierCard` that `getModifiers` throws away) — `format @Card` yields the `{card:"Name":"code":"id"}` token `GameMessage.vue` turns into a hoverable span — falling back to `log.attackOfOpportunityIgnored` when there is no card. Keys live in `frontend/src/locales/en/log.json`.

**An ignored AoO still counts as "made against you."** `HistoryAttacksOfOpportunity` is only incremented in `After (EnemyAttack details)` — a path an ignored attack never reaches — so every card gating on "the first attack of opportunity each round/turn" via `getHistoryField RoundHistory/TurnHistory` saw a counter stuck at 0. The mandatory-ignore branch now pushes `UpdateHistory iid (HistoryItem HistoryAttacksOfOpportunity 1)`. `getHistory RoundHistory` is `roundHistory <> phaseHistory` and `UpdateHistory` writes `phaseHistoryL`, so the count is live mid-round.

Cards granting `IgnoreAttacksOfOpportunity`: Trench Armor (3), Andy Van Nortwick, Prophesiae Profana (5) (`TabooList20` variant only — the untabooed one grants `MayIgnoreAttacksOfOpportunity`). The first two also carry an asset-meta "unspent this round" flag reset on `BeginRound`; that flag was consumed by **any** `EnemyAttack` against the controller, so an ordinary enemy-phase attack silently burned the ignore. Both now guard on `details.kind == AttackOfOpportunity`.
