Implementing the full **The Drowned City** campaign (campaign id `"11"`, cycle `tdc`, "The Risen Deep").

- **Player cards** (codes 110xx–112xx, pack `tdcp`) were already implemented and git-tracked before this work began (`Asset/Cards/TheDrownedCity.hs`, `Event/Cards/TheDrownedCity.hs`, `Skill/CardDefs/TheDrownedCity.hs`, `Treachery/CardDefs/TheDrownedCity.hs`). Do NOT redo these.
- The work being added is the **campaign/encounter layer**: codes 115xx–117xx (range 11501–11766), pack `tdcc` (262 cards: 88 location, 45 treachery, 38 enemy, 25 asset/artifact, 24 act, 20 agenda, 12 story, 10 scenario).
- The encounter "Expedition" set is named `TdcExpedition` in `Arkham.EncounterSet` because Forgotten Age already owns `Expedition`.
- Campaign-wide rules: Flood levels, Artifacts, Alien Glyphs (use CampaignSpecific/ScenarioSpecific messaging, avoid new Message constructors), `Relentless` (added as a global `Keyword`), Alert/Patrol/Seal already existed. Task blocks render with the `compose.green` flavor modifier.
- All user-facing text goes through i18n (scope `theDrownedCity`). See [[feedback_i18n_card_implementation]].
- Source guide extracted to `/Users/halogenandtoast/Downloads/the-drowned-city/guide-default.txt` (use default `pdftotext`, not `-layout`/`-raw`).
- **Card data: prefer `.claude/data/cards.json`** (arkham.build) over the Downloads `the-drowned-city.json` — the Downloads export is MISSING card backs / double-sided info. The complete data (act/agenda backs, e.g. act `11504b` "Hibb's Roadhouse" is the *location* back of act `11504`) is in `.claude/data/cards.json`.
## Step 4 (scenarios 2-10) mechanics
- **Flood**: already in the engine (built for Innsmouth) — `IncreaseFloodLevel`/`DecreaseFloodLevel`/`SetFloodLevel` messages, `LocationFloodLevel` field, `FloodedLocation`/`FullyFloodedLocation`/`PartiallyFloodedLocation` matchers. Reuse; do not rebuild.
- **Vertical "level" (Western Wall / Obsidian Canyons)**: model via grid Position — `placeInGrid (Pos row col) loc` (row 0 = level 1). A location's level = its `LocationPosition` row + 1 (`field LocationPosition locId` → `Pos r _`). Closest template is `Scenario/Scenarios/ALightInTheFog.hs` (Innsmouth vertical-grid descent WITH flood).
- **getLocationLevel** must take the *investigator* (via `getMaybeLocation` then `field LocationPosition`), NOT a bare LocationId in an early helper module — otherwise the `Projection Location` instance isn't visible. Mirror `Scenarios/ToTheForbiddenPeaks/Helpers.getLevel`. Lives in the scenario Helpers (compiled late).
- **Scenario → next campaign step (direction branch)**: scenarios import `setNextCampaignStep` selectively from `Arkham.Campaign.Import.Lifted`, and import the `CampaignSteps` patterns *selectively* (`import ...CampaignSteps (pattern TheDrownedQuarter, ...)`) — importing the whole module collides with the scenario's own newtype (e.g. the `TheWesternWall` step-pattern vs the `TheWesternWall` scenario type).
- **Rotating Central Chamber (The Apiary)**: Central Chamber is centre of a 4-location ring, connected only to the location "beneath" it; "rotate clockwise/counter" changes which. Model the *facing* (GridDirection) in scenario meta; Central Chamber's HasModifiersFor connects it to the location at centre+facing AND applies the existing UI rotation modifier (`UIModifier (Rotated degrees)`, as FateOfTheVale uses `UIModifier $ Rotated 90`). A ScenarioSpecific "rotate" message updates the facing/degrees. IMPLEMENTED: `Scenarios/TheApiary/Helpers.hs` holds `ApiaryMeta {centralChamberFacing :: GridDirection}` (default GridDown) + `getCentralChamberFacing`/`rotateFacingClockwise`/`rotateFacingCounterClockwise`/`facingDegrees`. Scenario `TheApiary.hs` handles `ScenarioSpecific "rotateCentralChamber" v` (toResultDefault "clockwise"). Act `The Hive Mind` pushes `scenarioSpecific "rotateCentralChamber" ("clockwise"|"counterclockwise")` on its round-end coin flip.
- **The Apiary setup branches on `getHasRecord TheExpeditionHeadedWest`**: west gathers Pilgrims+DarkCult, act2 = Lost Pilgrims, removes Mother; east gathers StarSpawn(only Infected)+Stowaways, act2 = The Hive Mind, removes Maria Rivera. Shared gather: TheApiary, CosmicLegacy, ElderMist, TheInescapable, StrikingFear. All Apiary locations + story enemies/assets are `setAside` (they enter via Revelations). New campaign-log keys added to `Key.hs` (auto-wired centrally — generic `show`-to-words formatter, single `TheDrownedCityKey` wrapper, no CampaignLogKey.hs edits needed): `ThePilgrimsWereSaved` (R1), `ThePilgrimsWereDevoured` (R2), `TheInvestigatorsExterminatedTheAlienParasites` (R3). `GrislyMask` recorded if any investigator controls the asset at scenario end. 29 card behaviors fanned out via `.claude/workflows/apiary-cards.js`.
- **Middle-scenario flow**: each scenario's resolution branches on `getHasRecord TheExpeditionHeadedWest/East` and pushes the next via setNextCampaignStep. West: WW→DrownedQuarter→Apiary→GrandVault→CourtOfAncients→ObsidianCanyons; East = reverse; both converge at Sepulchre → Interlude III (The Awakening) → Interlude IV (Return to Arkham) → Doom of Arkham I → II → Epilogue. Scenarios cross themselves off the "R'lyeh map" (crossOut) on completion.

- `scenarioSpecific`/`campaignSpecific` are LIFTED actions that push internally — call directly, do NOT wrap in `push` (else "Could not deduce IsMessage/ReverseQueue"). Storm/Disturbance/Apiary-rotation counters live in scenario meta via a tiny typed `<Scenario>Meta` newtype + `getScenarioMeta`/`setScenarioMeta` (note `setScenarioMeta` is re-exported by `Scenario.Import.Lifted` — do NOT also import it from `Arkham.Helpers.Scenario`, it's redundant); a `get<Counter> :: (HasGame m, Tracing m)` helper reads it.
- **Recurring card build-fix patterns** (from Apiary+Grand Vault+Court+Obsidian workflow rounds): \`field <InvestigatorField> iid\` needs \`import Arkham.Projection\` + \`Arkham.Investigator.Types (Field (InvestigatorResources/InvestigatorClues/...))\`; a treachery reads its own resources via \`attrs.resources\` (OverloadedRecordDot); \`playerLimit PerRound $ restricted ...\` must wrap the WHOLE \`restricted\` (it returns Ability, not AbilityType); (0) `\lift ->`/`lift` lambda binders SHADOW the `lift` from Control.Monad.Trans (via umbrella) → rename (e.g. `greatLift`); ambiguous `Discarded` (umbrella Message ctor vs Matcher window) → `import ...Import.Lifted hiding (Discarded)`; `GridUp/GridDown/GridDirection` need `import Arkham.Direction`; `EnemyPhase` needs `import Arkham.Phase`. (1) redundant-import via the `<Type>.Import.Lifted` umbrella — remove the explicit `Arkham.Cost`/`Arkham.Message.Lifted.Card`/`Arkham.I18n`/`Arkham.Helpers.Query (getSetAsideCard/getLead)` import even if the symbol IS used; (2) `deriving anyclass (X, HasAbilities/HasModifiersFor)` + a manual instance → remove from deriving; (3) card importing `Arkham.GameEnv` directly causes a MODULE CYCLE → use `import {-# SOURCE #-} Arkham.GameEnv (...)` (hs-boot exports getDistance etc.); (4) `Field(..)` wildcard pulls a clashing ctor (e.g. `EnemyDefeated`) → narrow to `Field (EnemyDoom)`; (5) `selectOne`/query needs `Tracing m` not just `HasGame m`; (6) `enemyAt` takes a LocationId, use the `EnemyAt LocationMatcher` ctor for a matcher; (7) scenario Helpers that don't import an umbrella need explicit `Arkham.Id` (LocationId), `Arkham.Classes.Query` (selectCount/`<=~>`); ReverseQueue already implies Tracing+HasGame.
