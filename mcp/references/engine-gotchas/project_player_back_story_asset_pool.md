---
title: project_player_back_story_asset_pool
description: "Player-back campaign-ally story assets must live in allPlayerAssetCards, not allEncounterAssetCards, or they reshuffle into the encounter deck on defeat"
---

A single-sided **player-back** story asset (a campaign ally you can add to your deck — e.g. Hemlock Vale guests/residents) must be registered in `allPlayerAssetCards`, NOT `allEncounterAssetCards`, in `Arkham/Asset/Cards.hs`. Those lists are hand-maintained (not generated by cards-discover, which only re-exports modules).

`lookupCard` wraps a code as `EncounterCard` if it's in `allEncounterCards`. If a player-back ally is misfiled there, on defeat its `Discard` emits `Discarded (AssetTarget _) _ (EncounterCard ec)`, the scenario runner adds `ec` to the encounter discard pile, and `ShuffleEncounterDiscardBackIn` later reshuffles it into the encounter deck — so it gets dealt as a mythos card (issue #4926, Dr. Rosa Marquez 10702).

Fix is just the pool move; no engine/card-def change. The card def keeps `storyAsset … <EncounterSet>` (the encounter set stays for `CardIsStoryAsset` matching; `gatherEncounterSet` filters `allEncounterCards` so a player-pool card is correctly excluded from encounter-deck gathering).

The engine already does the right thing for player cards via `handleDiscarded` (`Arkham/Investigator/Runner/Card.hs`): `shouldDiscard = owned-by-someone`. **Owned** → owner's discard pile; **unowned** (scenario-created and handed out) → dropped from play, never in the encounter discard. So "unowned ⇒ removed from game" needs no extra code once the card type is correct.

Contrast: the *tracked* residents (Judith/Mother Rachel/Bertie etc.) legitimately stay in the encounter pool because they are **double-sided** (`cdOtherSide = Just "…b"`), with the player side registered separately as the `…b` card. Double-sided assets also hit `removeFromGame` directly in the `Discard` handler via the `(toCardDef a).doubleSided` check. See [[feedback_no_invented_abilities]].

`allEncounterAssetCards` in `Asset/Cards.hs` is literally commented "-- with encounter backs" — the invariant is double-sided only. Single-sided story-asset **deck rewards** (Mi-Go Incursion: Universal Solvent 85029, Pet Oozeling 85030, Mi-Go Weapon 85031, Lt. Wilson Stewart 85032) crash deck load with `Unknown card "…"` because `lookupPlayerCardDef` (Decklist load) only sees `allPlayerCards`; move them to `allPlayerAssetCards` (issue #5095).

**Gather coupling:** if a scenario set-asides such a card via `gatherAndSetAside <Set>` (which calls `gatherEncounterSet`, filtering `allEncounterCards`), moving the card OUT of the encounter pool drops it from that gather → the stories' `getSetAsideCard`/`selectJust` fail. Compensate with an explicit `setAside [Assets.foo, …]` right after the gather (setAside's `notFoundInDeck = genCard` builds the now-player card into `setAsideCardsL`). Did both in TheBlobThatAteEverything setup.
