The FAQ v2.5 "Ultimatums and Boons" variant system (2026-07: 11 Boons + 19 Ultimatums landed; ~18 Refractions + Challenges planned in follow-up docs) lives on:

Ultimatums drop additions: `settingsRolledUltimatumOrBoon` (Ultimatum of Ultimatums per-game roll, set in Game/Runner StartScenario, included by `activeUltimatumsAndBoons`), `settingsScreamedAllies` (+`RecordScreamedAlly` msg), `scenarioUseHardExpertReference` on ScenarioAttrs (Malevolence; honored by isEasyStandard/isHardExpert), chaos-bag deltas inside ChaosBag `SetChaosTokens` (BrokenPromises/Failure), Agony choice-filter in Runner/Damage, deck validation in frontend `deckRestrictions.ts` (Highlander/Induction/Exile/Orthodoxy — uses RAW selection, ignores runtime toggle; Chaos = unenforced honor rule). Engine lessons: messages pushed from the scenario dispatcher run AFTER entity pushes for the same message (mode dispatches before entities; effects created by push can arrive too late — prefer computed modifiers or queue surgery), EndOfScenario's handler clearQueues, and campaign step transitions can run in `This` (campaign-only) mode where the scenario dispatch doesn't exist — campaign-lifecycle hooks (e.g. Scream deck cleanup) belong in Campaign/Runner's NextCampaignStep handler, not the scenario-side dispatcher.

- **Types**: `Arkham.UltimatumsAndBoons.Types` — discrete `data Boon` and `data Ultimatum` (empty until that drop), merged as `data UltimatumOrBoon = Ultimatum Ultimatum | Boon Boon` for storage/Source/Target/combined-catalog operations (user prefers discrete types). Custom JSON FLATTENS the union — `Boon BoonOfHades` ⇄ `"BoonOfHades"` — so the wire format/saved games/frontend see plain strings; keep that invariant when adding Ultimatums. Only implemented entries get constructors.
- **Storage**: `Settings.settingsUltimatumsAndBoons :: Set UltimatumOrBoon` + `settingsUltimatumsAndBoonsEnabled :: Bool` (runtime kill switch, message `SetUltimatumsAndBoonsEnabled`). NOT CampaignOption/CampaignLog — works identically in standalone (no Campaign) and needs no per-campaign HandleOption handlers. Set at creation via `CreateGamePost.ultimatumsAndBoons`.
- **Single gate**: `activeUltimatumsAndBoons :: Settings -> Set UltimatumOrBoon` (empty when disabled); every hook reads through it or `hasUltimatumOrBoon`/`getActiveUltimatumsAndBoons` (`Arkham.UltimatumsAndBoons`).
- **Dispatch = tarot pattern**: `UltimatumOrBoonSource` Source constructor; `HasModifiersFor UltimatumOrBoon` fans in from `Game.preloadModifiers`; `ultimatumOrBoonAbilities` fans in from `HasAbilities Game`; ability uses + `UseAbility → Do msg` claim + PlayCard observation dispatched from `Arkham.Scenario` RunMessage catch-all via `runUltimatumsAndBoonsMessage`. Ability limits give "first time each game" (`playerLimit PerGame`) etc. for free.
- **Deckbuilding hooks** live in the two `InitDeck` handlers (Campaign/Runner campaign, Scenario/Runner standalone) — Morrígan weakness flow (`morriganWeaknessMessages`, pre-samples the random branch per choice for undo/replay safety), Ancients +5 XP (campaign only).
- Frontend: catalog + i18n in `frontend/src/locales/en/gameBoard/ultimatumsAndBoons.json`, selection card in GameOptions.vue, toggle in Settings.vue (SetAsIfRuling pattern), log section in CampaignLog.vue reading `game.settings`.

**How to apply:** to add an Ultimatum/Refraction: add enum constructor, add its case to `HasModifiersFor`/`ultimatumOrBoonAbilities`/`runUltimatumsAndBoonsMessage` (or a guarded check at the specific engine call site), add frontend catalog entry + i18n.
