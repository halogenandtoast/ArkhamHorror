**Source:** `local-packages/bounded-enum-th/src/BoundedEnum/TH.hs`.

Stock deriving refuses any constructor with fields. This splice computes each
constructor's cardinality by `reify`ing its argument types and generates `toEnum`/
`fromEnum`/`minBound`/`maxBound` over the flattened space:

```haskell
data Color      = Red | Green | Blue deriving (Enum, Bounded)
data Chromatics = Monochrome | Full Color | TwoTone Color Color
$(deriveBoundedEnum ''Chromatics)

[minBound .. maxBound] == [Monochrome, Full Red, ..., TwoTone Blue Blue]
```

The general move: **derive the exhaustive list from the type instead of writing it down.**
A hand-maintained list of "all the things" is a latent bug the compiler cannot see; a
generated one is checked every build. (`Mercury.Common.Enumerable` is the companion
class for when `Bounded` genuinely doesn't fit, e.g. uninhabited types.)

**How to apply here:** the exact failure this prevents is recorded in memory —
`project_asset_event_builder_lists_are_manual`: `allAssets` / `allEvents` in `Asset.hs` /
`Event.hs` are hand-maintained builder lists while every other card type is generated by
`cards-discover --builders=`, and a forgotten entry is a runtime `error "Unknown asset"`
500 with card def, module and art all present. Children of Blood shipped 2 of 6 assets
registered. Either extend `cards-discover` to those two, or generate the list with TH —
but stop writing it by hand.
